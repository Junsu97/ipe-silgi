# 정보처리기사 실기 모의고사 문항 생성 규칙

## 출제 기준
- 한국산업인력공단 정보처리기사 실기(2020년 개정 NCS 기반). 필답형 20문항, 문항당 5점. 보기 없이 서술형 지문을 주고 용어·값·출력 결과를 쓰게 하는 단답형이 대부분이다.
- 실제 기출의 «유형과 난이도»만 따르고, 실제 기출 문장·코드를 그대로 복제하지 말고 새로 만든다(저작권).
- 같은 폴더의 `existing.md` 에 이미 출제된 문항 목록이 있다. **서브 주제와 정답이 겹치지 않게** 새 주제를 고른다.

## 지문·답·해설 형식
- 지문(question)은 시험 문체로 쓴다. 예: "다음 C언어 코드의 출력 결과를 쓰시오.", "다음 설명에 해당하는 용어를 쓰시오.", "다음 설명의 괄호 ( ① ), ( ② )에 들어갈 알맞은 용어를 쓰시오." 존댓말 금지. 코드 문제는 지문 안에 코드를 넣지 말고 `code` 필드에 넣는다.
- 지문 안에 표가 필요하면 마크다운 표(`| a | b |` + `|---|---|`)를, SQL 문장이나 명령어를 제시해야 하면 ``` 코드 펜스를 쓴다.
- `parts`: 답 칸 목록. 단일 답이면 `[{"label":"정답","answers":[...]}]`, 빈칸이 여러 개면 `[{"label":"①","answers":[...]},{"label":"②","answers":[...]}]`. 코드 출력 문제는 `[{"label":"출력 결과","answers":["정확한 출력"]}]` 하나이며, 출력이 여러 줄이면 answers[0] 안에서 `\n` 으로 구분한다.
- answers[0] 이 화면에 보여 줄 대표 정답이고, 나머지는 채점 시 인정할 변형(한글 용어, 영문 전체 표기, 영문 약어, 흔한 동의어, 한·영 병기 「용어(English)」). 채점기는 대소문자·공백·마침표·하이픈·괄호를 무시하고 비교하므로 그런 변형은 넣지 않아도 된다.
- 지문에 정답 단어가 그대로 노출되면 안 된다(예: 「형상통제위원회」가 지문에 있으면 「형상 통제」는 답이 될 수 없음).
- `explanation`: 해설 3~6문장. 왜 그 답인지, 헷갈리는 비슷한 용어와의 구분, 코드 문제면 핵심 추적 과정(변수 값 변화).
- `difficulty`: 하/중/상. 한 영역 안에서 섞되 «중»을 중심으로 한다.
- 코드 문자열 리터럴과 출력에는 ASCII 만 사용한다(한글 금지 — 실행 환경 인코딩 문제).
- `selfCheck`: 직접 수행한 검증 내용(코드: 실제 실행 결과 또는 단계별 추적표, 개념: 정답이 유일한 이유).

## 코드 문제 규칙 (C / Java / Python)
- 코드는 완전해야 한다(C: #include, main 포함 / Java: `public class Main` 과 main 메서드, 보조 클래스는 같은 파일에 non-public / Python: 바로 실행 가능).
- 결정적이어야 한다: 난수, 시간, 입력(scanf/input/Scanner), 해시 순서 의존(파이썬 set 출력 순서 등) 금지. 파이썬 딕셔너리는 삽입 순서를 따르므로 사용 가능.
- 출력은 1~4줄의 짧은 값(정수·문자·문자열)으로, 형식이 단 하나로 결정되어야 한다. 끝 공백·부동소수 표현처럼 모호한 출력 금지. 실수 출력은 피하고 꼭 쓰면 소수 자릿수를 포맷으로 고정한다.
- 난이도는 실제 실기 수준: 15~30줄, 반복문·조건문·함수·배열(포인터)·클래스가 섞여 «손으로 추적»해야 풀리는 문제. 한 줄짜리 상식 문제 금지.
- 미정의 동작(UB) 금지: 미초기화 변수, 배열 범위 초과, 한 식 안에서 같은 변수 두 번 수정(i++ + i++ 류), 시퀀스 포인트 문제, char 오버플로, 음수·범위 초과 시프트, 정수 오버플로, printf 인자-포맷 불일치. int 는 32비트로 가정.
- Java 는 equals vs == 같은 애매한 주제 금지. 문자열 연결 우선순위(1+2+"a")는 의도된 함정으로 써도 된다.
- 검증 환경: 이 폴더(`gen/`) 아래에 자신의 영역 이름으로 하위 폴더를 만들어 파일을 쓴다. Bash 는 Git Bash 이다. Java 17(javac/java)과 Node 22 가 설치되어 있다. **C 컴파일러와 Python 은 없다.**
  - Java: 반드시 `Main.java` 로 저장하고 `javac Main.java && java Main` 으로 실제 실행하여 출력을 answers[0] 에 그대로 적는다.
  - C: 컴파일러가 없으므로 (1) 단계별 추적표를 selfCheck 에 쓰고 (2) 동일 의미의 Java 또는 JavaScript(Node)로 이식하여 실행해 출력을 교차 확인한다(int 32비트·정수 나눗셈 절삭·printf 포맷 동일성 주의, 포인터는 배열 인덱스로 이식).
  - Python: 인터프리터가 없으므로 (1) 단계별 추적표를 selfCheck 에 쓰고 (2) 슬라이싱·음수 인덱스·// 와 % 의 부호 규칙·정수/문자열 변환 의미를 정확히 지켜 JavaScript 로 이식해 Node 로 교차 확인한다.

## 개념 문제 규칙
- `type` 은 "short", `code` 는 빈 문자열.
- 정답이 «유일»해야 한다: 지문의 설명을 만족하는 다른 용어가 없도록 핵심 식별 단서(고유 특징·수치·약어 힌트)를 넣는다.
- 표준 교재(수제비·시나공·이기적)와 NCS 학습모듈에서 통용되는 정의·용어를 쓴다. 특정 교재에만 있는 신조어 금지.
- 빈칸형(①②③)은 각 빈칸의 답이 서로 다른 용어여야 하며 parts 에 빈칸 순서대로 넣는다.
- 계산형(서브네팅, 스케줄링, 페이지 부재, 커버리지, SQL 결과 등)은 explanation 에 풀이 과정을 단계별로 쓰고 답이 하나의 수·문자열로 떨어져야 한다. SQL 결과는 표준 SQL 의미(NULL 집계 제외, 조인 행 수, GROUP BY 결과 행)로 수작업 실행해 확정한다.

## 출력 파일 형식
지시받은 경로에 아래 구조의 JSON 파일을 UTF-8 로 저장한다(BOM 없이). 다른 설명 없이 JSON 만.

```json
{
  "questions": [
    {
      "subtopic": "짧은 서브 주제명(정답 단어 포함 금지)",
      "type": "code | short",
      "language": "C | Java | Python | SQL | ''",
      "question": "지문",
      "code": "코드 또는 빈 문자열",
      "parts": [{"label": "정답", "answers": ["대표 정답", "변형1", "변형2"]}],
      "explanation": "해설",
      "difficulty": "하 | 중 | 상",
      "selfCheck": "검증 기록"
    }
  ]
}
```

작업 순서: 서브 주제를 먼저 고른다(existing.md 와 겹치지 않게) → 각 문제를 작성한다 → 규칙대로 직접 검증한다(코드 문제는 실행/이식 실행, 개념 문제는 정답 유일성 점검) → 검증 결과를 selfCheck 에 적는다 → JSON 파일을 저장한다 → 최종 답변은 「저장 경로와 문항 수, 서브 주제 목록」만 짧게 적는다.
