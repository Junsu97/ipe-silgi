# 문항 검증 규칙

입력: 지시받은 `gen/<영역>.json` 의 `questions` 배열. 각 문항을 배열 index(0부터) 로 식별한다. 출제자의 `selfCheck` 는 믿지 말고 독립적으로 다시 검증한다.

채점기 동작(참고): 개념 문제는 answers 와 비교할 때 대소문자·공백·마침표·하이픈·괄호·쉼표를 모두 제거한 뒤 완전 일치로 판정한다. 코드 출력 문제는 줄 단위로 비교(각 줄 앞뒤 공백 제거, 연속 공백은 하나로, 빈 줄 제거)하며 대소문자를 구분한다.

## 코드 문제 — 검증자 A (실행 검증)
- Java: 코드를 `Main.java` 로 저장 → `javac Main.java && java -cp . Main` (CLASSPATH 환경변수 때문에 `-cp .` 필요) → 실제 출력과 answers[0] 을 문자 단위로 비교(마지막 줄바꿈만 무시).
- C: 컴파일러가 없다. 코드를 의미 그대로 Java 또는 Node(JavaScript) 로 이식해 실행한다(int 32비트, 정수 나눗셈 절삭, 포인터 → 인덱스, printf 포맷 → 수동 포맷, char → 정수 코드). 이식이 어려운 부분은 손 추적표로 확정한다. 추가로 UB(미초기화·범위 초과·시퀀스 포인트·오버플로·시프트 범위)와 컴파일 에러(선언 누락·세미콜론·헤더)를 점검한다.
- Python: 인터프리터가 없다. 손 추적표(각 반복마다 변수 상태)를 먼저 만들고, JavaScript 로 이식해 Node 로 교차 확인한다(슬라이싱 경계, 음수 인덱스, // 와 % 의 음수 규칙, 정수/문자열, 리스트 `[1, 2]`·튜플 `(1, 2)`·딕셔너리 `{'a': 1}` 출력 형식, True/False, print 의 sep=' ' end='\n'). 두 결과가 다르면 파이썬 의미론 기준으로 재추적해 확정한다.
- 판정: 정답이 틀림 / 컴파일·실행 에러 / UB·비결정적 / 출력 형식이 둘 이상으로 해석 가능 → `fail` (reason 에 실제 출력 또는 올바른 추적 결과를 반드시 적는다). 사소한 표현·난이도 취향은 `pass` + note.

## 코드 문제 — 검증자 B (회의적 검토)
- 출제자 정답이 «틀렸다»고 가정하고 반박을 시도한다. selfCheck 를 읽지 않은 셈 치고 자기 추적표를 먼저 완성한 뒤 비교한다.
- 점검: (1) 손 추적으로 최종 출력을 문자 단위로 확정(공백·줄바꿈·부호·자릿수), (2) 컴파일 가능성(선언·타입·세미콜론·import·클래스 이름·접근 제어자·들여쓰기), (3) C UB, (4) Java 정수 나눗셈·char 승격·문자열 연결 우선순위·static 초기화 순서·오버라이딩 vs 오버로딩·finally 와 return, (5) Python 슬라이싱·별칭·정수 나눗셈·불변성·딕셔너리 순서·스코프, (6) 출제 적합성(실기 수준 15~30줄·지문 명확·ASCII 리터럴·답 유일).
- 보조 실행이 필요하면 Java/Node 로 이식 실행해도 된다. 단 손 추적을 반드시 먼저 한다.
- 판정: 추적 결과가 정답과 다르거나 (2)~(5) 의 실질 결함 → `fail`. (6) 수준의 가벼운 문제 → `pass` + note. 확신이 없으면 `fail`.

## 개념 문제 — 검증자 (사실 + 출제 적합성)
1. 정확성: 지문 설명이 표준 교재(수제비·시나공·이기적)·NCS 학습모듈·전공 교과서 기준으로 사실인가. 수치(비트·홉·단계·계층·포트·연도)와 분류(생성/구조/행위, 대칭/비대칭, 계층별 장비)를 하나씩 대조.
2. 정답 유일성: 지문 설명을 «똑같이» 만족하는 다른 용어가 있는가. 있으면 `fail` 이고 reason 에 경쟁 답을 적는다. 지문에 정답 단어가 그대로 노출되어 있어도 `fail`.
3. 계산형(SQL 결과·서브네팅·스케줄링·페이지 부재·커버리지): 처음부터 다시 풀어 값이 일치하는지 확인. SQL 은 표준 SQL 의미(NULL 집계 제외, 조인 행 수, GROUP BY 결과 행)로 수작업 실행. 필요하면 Node 로 계산 코드를 돌려 확인(SQL 엔진 없음).
4. 해설 정확성: 해설 속 보조 설명·비교 용어가 틀리지 않았는가.
5. 형식: 실기 문체("…를 쓰시오."), 빈칸 ①②③ 과 parts 순서·개수 일치, 실기 수준(단순 상식 아님, 지엽적·특정 교재 전용 용어 아님), 같은 파일 안 문항끼리 정답·서브 주제 중복 없음.
6. 정답 변형 보충: 수험생이 정당하게 쓸 수 있는 다른 표기(한글/영문/약어/허용 동의어/「~기법」「~패턴」 접미, 숫자 문제의 단위 유무)를 `extraAnswers` 에 같은 label 로 추가한다. 틀린 표기는 넣지 않는다.
- 판정: 1~5 의 실질 오류 → `fail`(reason 에 근거·올바른 값). 표현이 어색한 정도 → `pass` + note. 확신이 없으면 `fail`.

## 출력 파일 형식
지시받은 경로에 UTF-8(BOM 없음) JSON 으로 저장. 모든 index 를 빠짐없이 넣는다.

```json
{
  "results": [
    {
      "index": 0,
      "verdict": "pass | fail",
      "reason": "판정 근거(fail 이면 올바른 값·경쟁 답 포함)",
      "extraAnswers": [{"label": "정답", "answers": ["추가 인정 표기"]}],
      "note": "pass 인 경우의 가벼운 개선 의견(선택)"
    }
  ]
}
```

최종 답변은 「저장 경로 + index 별 pass/fail 한 줄 요약」만 짧게.
