# 묶인 빈칸 나누기 규칙

대상: `data/imported-sets.json` 중 지시받은 회차의 **모든 문항**. 원본 파일은 수정하지 않는다.
목표: 휴대폰에서 칸마다 답을 쓰고 칸별로 채점되게 `parts` 를 다시 짠다.

## 채점기 동작 (알고 판단할 것)
- `type: "short"`: 칸마다 입력란 1개. 답과 비교할 때 대소문자·공백·`.-_·/()[]{}'",:;!?~→⇒>` 를 지우고 완전 일치. 예) 「포인트 투 포인트(Point-to-point)」는 「포인트투포인트pointtopoint」로 바뀌므로, 「포인트 투 포인트」만 쓰면 **오답**이다 → 인정 답안에 한글만·영문만 표기를 따로 넣어야 한다.
- `type: "code"`: 여러 줄 입력란 1개. 줄 단위 비교, 대소문자 구분. **실제 코드 실행 결과(출력)** 에만 쓴다.
- `parts` 의 각 원소가 입력란 1개다. `label` 이 입력란 위에 표시된다.
- `unordered: true` 면 칸 순서와 상관없이 맞으면 정답(예: 「이상 현상 3가지를 쓰시오」).

## 문항별 판단
1. **빈칸이 여러 개인 문항** (지문에 ( ① ), (가), [A], (1), ㄱ 등 빈칸이 여러 개, 또는 답에 번호가 붙은 줄이 여러 개):
   - 칸 하나당 part 하나. `label` 은 **지문의 빈칸 표기를 그대로**(①, (가), A, (1), ㄱ …). 저장된 답의 번호 표기가 지문과 다르면 지문 기준으로 맞춘다.
   - 각 칸 `answers[0]` 은 대표 답(번호 표기 「(가)」「A.」「1.」 등 제거). 이어서 인정 표기를 넣는다: 괄호 안·밖을 나눈 표기(「허브 앤 스포크(Hub & Spoke)」→ 「허브 앤 스포크」, 「Hub & Spoke」), 「~ 결합도」「~ 계층」 같은 접미 유무, 흔한 한글/영문/약어. 틀린 표기는 넣지 않는다.
   - 「(A) n > 0 or n >= 1 or …」처럼 「or / 또는」으로 여러 답이 적힌 칸은 각각을 인정 답안으로 나눈다.
   - 한 줄에 「① values ② select …」처럼 묶였거나 「도메인, 개체, 참조」처럼 쉼표로 묶였어도 지문 빈칸이 여럿이면 나눈다.
2. **보기 기호를 고르는 문항**(답이 ㄱ, ㄴ, ㉡, ④ 같은 기호): 칸별로 나누고, 기호 단독과 「기호+용어」 둘 다 인정(예: 「ㄷ」, 「ㄷ. 개체」 → 정규화로 둘은 다르므로 둘 다 넣는다). 기호 문자는 원문과 같은 문자를 쓴다.
3. **답 하나 + 다른 표기 메모**(「애자일\n(애자일 방법론, 애자일 기법 등)」, 「Observer\n(또는 Observer Pattern)」, 「[아래 모두 답]…」): `type: "short"`, part 1개, 메모의 표기들을 인정 답안으로 펼친다. 「등」은 버린다.
4. **순서가 무관한 나열**(「~ 3가지를 쓰시오」 등 지문이 순서를 요구하지 않음): 칸으로 나누고 `unordered: true`. 지문이 순서를 요구하면(「순서대로」, 단계 순서) false.
5. **실제 프로그램 출력**(C·Java·Python 실행 결과, SQL 조회 결과 표): **그대로 둔다**(override 하지 않음). 단 출력이 「두 가지 중 하나」로 갈리면(「… 또는 …」) `type: "code"` 로 두고 answers 에 두 출력을 각각 넣는다.
6. **SQL·코드를 통째로 작성하는 문항, 서술형**: 그대로 둔다.
7. **두 값을 묻는 계산 문항**(「계산식 : … / 예상 개발 기간 : 20개월」, 「Cardinality : 5 / Degree : 4」, 「Fan-in : 3 / Fan-out : 2」): 칸으로 나누고 label 은 지문 용어(「계산식」「결과」, 「Cardinality」「Degree」). 숫자 칸은 단위 유무(「20」「20개월」)를 둘 다 인정. 계산식 칸은 흔한 등가 표기 몇 개를 넣는다.

## 출력
`C:\workspace\ipe-silgi\data\answer-overrides\<회차키>.json` (UTF-8, BOM 없음). **바꾸는 문항만** 넣는다. 바꿀 것이 없으면 `{}`.

```json
{
  "past-2020-1-9": {
    "type": "short",
    "parts": [{ "label": "(가)", "answers": ["원자성", "Atomicity", "원자성(Atomicity)"] },
              { "label": "(나)", "answers": ["독립성", "격리성", "Isolation", "독립성(Isolation)"] }],
    "unordered": false,
    "reason": "빈칸 (가)(나) 분리"
  }
}
```

## 해설 정리
`data/explanations/<회차키>.json` 의 해당 문항 해설에 「저장된 답의 (1), (2)는 빈칸 A, B에 해당한다」처럼 **번호 표기 차이를 설명하는 문장**이 있으면, 칸을 지문 표기로 맞췄으므로 그 문장만 지운다. 다른 문장은 건드리지 않는다. 자기 담당 회차 파일만 수정한다.
